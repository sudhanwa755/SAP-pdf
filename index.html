ABAP Foundations & Syntax Mechanics

1.1What is ABAP? Architecture & Mental Model

ABAP (Advanced Business Application Programming) is SAP's 4th-generation, enterprise-grade programming language. Unlike general languages (like Python or C++), ABAP does not run directly on OS hardware. Instead, it runs inside the SAP Application Server, where it is tightly bonded to the SAP relational database and the central ABAP Data Dictionary (DDIC).

📌 Student Mental Model: The SAP 3-Tier Architecture
Always visualize where your code runs:
  • Presentation Layer (SAP GUI / Fiori Browser): Where user inputs data and views screens.
  • Application Layer (Where your ABAP executes): Performs business logic, validations, loops, and calculations.
  • Database Layer (SAP HANA / Oracle / DB2): Stores business master & transactional tables (e.g., VBAK, KNA1).
Rule of thumb: Keep heavy business computations on the database or application layer, never push raw messy data to the presentation layer!
📊 Visual Concept Diagram: The SAP 3-Tier Enterprise Architecture
💡 Student Visual Takeaway: ABAP code runs inside the Application Server. Internal tables live in the App Server RAM, so looping through an internal table does NOT generate expensive network calls to the Database Server!

1.2Basic Executable Report Structure

Every classic executable ABAP program starts with the REPORT keyword followed by a program name (custom customer programs must begin with Z or Y).

📐 SYNTAX BLUEPRINT • WHERE & WHY TO USE WHAT TEMPLATE STRUCTURE 
REPORT <program_name> [MESSAGE-ID <msg_class>].

DATA <variable_name> TYPE <data_type> [VALUE <initial_value>].

WRITE: [/] <expression_1>, <expression_2>.
Where & Why to Use What:
  • REPORT <program_name>: [Mandatory] Declares this program as an executable type 1 report. Customer reports MUST begin with Z (or Y).
  • DATA <variable_name> TYPE <data_type>: [Where to use]: Allocates typed variable space in session memory.
  • WRITE: / <val>: [Where to use]: Outputs values to the classic list output. Slash / forces cursor to move to a NEW LINE.
  • . (Period): [Mandatory]: Every statement in ABAP MUST conclude with a period. Omitting it is the #1 syntax error for newcomers!
💻 WORKING PRACTICAL CODE • LINE-BY-LINE COMMENTED ABAP 7.40+ EXECUTABLE 
REPORT zrpr_242_first_program.

" 1. Allocate a string variable in memory
DATA lv_name TYPE string.

" 2. Assign text value to the variable
lv_name = 'ABAP Learner'.

" 3. Send formatted greeting to the classic SAP list screen
"    The slash (/) forces output onto a brand new line
WRITE: / 'Welcome to SAP ABAP:', lv_name.
🖥️ CONSOLE / LIST OUTPUT 
Welcome to SAP ABAP: ABAP Learner

1.3Comments in ABAP

ABAP provides two distinct comment mechanisms: Full-line comments (*) and Inline comments (").

📐 SYNTAX BLUEPRINT • WHERE & WHY TO USE WHAT TEMPLATE STRUCTURE 
* <Full-line comment: Asterisk MUST be in column 1 (first character of line)>

<abap_statement> " <Inline comment: Double-quote can appear anywhere after code>
Where & Why to Use What:
  • * (Asterisk): [Where to use]: Use at the very start of a line to comment out entire paragraphs or code blocks.
  • " (Double Quote): [Where to use]: Use after a statement to explain why a specific business condition exists.
💻 WORKING PRACTICAL CODE • LINE-BY-LINE COMMENTED ABAP 7.40+ EXECUTABLE 
*=============================================================
* Program Name : ZRPR_242_FIRST_PROGRAM
* Purpose      : Demonstrates fundamental comment syntax in ABAP
* Author       : Student Notes Reference
*=============================================================

DATA lv_count TYPE i. " Variable to store active loop counter
💡 GOLDEN ABAP RULE: Write Meaningful Comments
Comment the business reason why code exists, not obvious syntax. For example, write " Exclude inactive customers per EU compliance rather than " check if status eq I.

1.4WRITE Statement Formatting Basics

The WRITE statement is the classic display engine. Using the chaining colon (:) allows grouping multiple write operations cleanly separated by commas.

📐 SYNTAX BLUEPRINT • WHERE & WHY TO USE WHAT TEMPLATE STRUCTURE 
WRITE: [/][<pos>][(<len>)] <expression_1>,
       [/][<pos>][(<len>)] <expression_2>.
Where & Why to Use What:
  • / (Slash): [Where to use]: Forces the output buffer to start at column 1 of the NEXT row.
  • <pos>: [Where to use]: Optional integer column index (e.g. WRITE: /10 'Name' starts at horizontal column 10).
  • (<len>): [Where to use]: Limits maximum rendered output width to truncate or preserve table columns.
  • : (Chaining Colon): [Where to use]: Avoids typing WRITE repeatedly; chained values are separated by commas.
💻 WORKING PRACTICAL CODE • LINE-BY-LINE COMMENTED ABAP 7.40+ EXECUTABLE 
DATA: lv_id   TYPE i VALUE 101,
      lv_role TYPE string VALUE 'Junior Consultant'.

" Demonstrating line breaks and horizontal column alignment
WRITE: / 'Employee Summary:',
       / '--------------------------------',
       / 'ID Number  :', lv_id,
       / 'Designation:', lv_role.
🖥️ CONSOLE / LIST OUTPUT 
Employee Summary:
--------------------------------
ID Number  :        101
Designation: Junior Consultant

1.5Common Elementary Data Types

ABAP provides built-in 1-character type codes as well as dynamic types. Selecting the correct data type is critical for memory management and financial arithmetic precision.

Type Full Name & Properties Syntax Blueprint & Declaration Where to Use in Business Logic
I 4-byte 32-bit Integer DATA lv_qty TYPE i. Loop counters, array indices, item counters.
P Packed Decimal (BCDs)
Mandatory for Money!		 DATA lv_amt TYPE p LENGTH 8 DECIMALS 2. Currency amounts, prices, taxes, weights, dimensions. Never use float for money!
F 8-byte Floating Point DATA lv_ratio TYPE f. Scientific calculations, logarithmic scales (subject to binary rounding quirks).
C Fixed-length Character DATA lv_code TYPE c LENGTH 10. Status codes (e.g., 'ACTIVE'), country codes, unit keys ('KG', 'PC').
N Numeric Text (0-9 only)
Leading zero padded		 DATA lv_doc TYPE n LENGTH 10. Sales order numbers, customer IDs, postal codes where leading zeros matter.
D Date (Fixed 8 chars) DATA lv_date TYPE d. " YYYYMMDD Calendar dates. ABAP supports automatic date math (e.g., lv_date + 7 is 1 week later).
T Time (Fixed 6 chars) DATA lv_time TYPE t. " HHMMSS Timestamps and processing clock recordings.
STRING Dynamic String DATA lv_text TYPE string. Variable-length descriptions, error messages, concatenated output text.
XSTRING Byte string (Hex) DATA lv_hex TYPE xstring. PDF raw binaries, image byte streams, encrypted tokens, attachments.
⚠️ EXAM & DEBUG WATCHOUT: The Floating Point Rounding Trap
Never use TYPE F for financial transactions, billing totals, or currency. TYPE F uses binary floating-point representation, causing minute precision errors (e.g., 0.00000001). Always declare money as TYPE P DECIMALS 2 or use SAP DDIC currency fields like VBAK-NETWR!

1.6Declaration Styles: Classic vs Modern Inline

In classic ABAP, all variables had to be declared at the top of the program. In modern ABAP (NetWeaver 7.40+), we use Inline Declarations (DATA(...)) right at the point of use.

📐 SYNTAX BLUEPRINT • WHERE & WHY TO USE WHAT TEMPLATE STRUCTURE 
" --- 1. CLASSIC EXPLICIT DECLARATION ---
DATA <var_name> TYPE <data_type> [VALUE <init_val>].

" --- 2. CHAINED DECLARATION ---
DATA: <var_1> TYPE <type_1>,
      <var_2> TYPE <type_2>.

" --- 3. MODERN INLINE DECLARATION (ABAP 7.40+) ---
DATA(<new_variable>) = <expression_or_assignment>.
Where & Why to Use What:
  • DATA(...): [Where to use]: Declare target variables on the fly during assignments, READ TABLE INTO DATA(...), or SELECT ... INTO @DATA(...).
  • Type Inference: The ABAP compiler automatically infers the exact type and length from the right-hand operand, eliminating repetitive type declarations.
💻 WORKING PRACTICAL CODE • LINE-BY-LINE COMMENTED ABAP 7.40+ EXECUTABLE 
" Classic approach
DATA lv_num1 TYPE i VALUE 50.
DATA lv_num2 TYPE i VALUE 30.

" Modern 7.40+ Inline Declaration: lv_result is automatically inferred as TYPE I
DATA(lv_result) = lv_num1 + lv_num2.

WRITE: / 'Inline Sum Result:', lv_result.
🖥️ CONSOLE / LIST OUTPUT 
Inline Sum Result: 80

1.7MOVE vs Direct Assignment

Always prefer the modern equals sign (=) over the archaic MOVE ... TO ....

💻 WORKING PRACTICAL CODE • LINE-BY-LINE COMMENTED ABAP 7.40+ EXECUTABLE 
DATA lv_source TYPE string VALUE 'Enterprise Resource Planning'.
DATA lv_dest   TYPE string.

" Modern standard: Clean, intuitive assignment
lv_dest = lv_source.

" Obsolete classic equivalent: Avoid in clean ABAP
MOVE lv_source TO lv_dest.

Conditions & Comparison Operators

2.1IF / ELSEIF / ELSE Branching

Use IF branching for multiple complex conditional tests.

📐 SYNTAX BLUEPRINT • WHERE & WHY TO USE WHAT TEMPLATE STRUCTURE 
IF <logical_condition_1>.
  <code_block_1>
ELSEIF <logical_condition_2>.
  <code_block_2>
ELSE.
  <fallback_code_block>
ENDIF.
Where & Why to Use What:
  • <logical_condition>: [Where to use]: Evaluates to TRUE or FALSE (e.g. lv_score >= 90).
  • ELSEIF: [Where to use]: Evaluated only if the preceding IF condition failed. Note: spelled as ONE word in ABAP (not ELSE IF)!
  • ENDIF.: [Mandatory]: Closes the condition block. Must conclude with a period.
💻 WORKING PRACTICAL CODE • LINE-BY-LINE COMMENTED ABAP 7.40+ EXECUTABLE 
DATA lv_score TYPE i VALUE 82.

" Evaluate academic grade bracket
IF lv_score >= 90.
  WRITE: / 'Grade: Distinction (A+)'.
ELSEIF lv_score >= 75.
  WRITE: / 'Grade: First Class (A)'.
ELSEIF lv_score >= 50.
  WRITE: / 'Grade: Pass (B)'.
ELSE.
  WRITE: / 'Grade: Remedial Action Required'.
ENDIF.
🖥️ CONSOLE / LIST OUTPUT 
Grade: First Class (A)

2.2CASE / WHEN Discrete Branching

When inspecting a single variable against fixed literal choices, CASE is faster and vastly more readable than multiple nested IF / ELSEIF chains.

📐 SYNTAX BLUEPRINT • WHERE & WHY TO USE WHAT TEMPLATE STRUCTURE 
CASE <variable_to_evaluate>.
  WHEN <literal_or_constant_1>.
    <action_1>
  WHEN <literal_or_constant_2>.
    <action_2>
  WHEN OTHERS.
    <default_action>
ENDCASE.
Where & Why to Use What:
  • CASE <variable>: [Where to use]: Evaluates one specific variable against discrete target values.
  • WHEN OTHERS.: [Where to use]: The safety fallback trigger if no prior WHEN matched.
💻 WORKING PRACTICAL CODE • LINE-BY-LINE COMMENTED ABAP 7.40+ EXECUTABLE 
DATA lv_dept_code TYPE c LENGTH 4 VALUE 'SAP'.

CASE lv_dept_code.
  WHEN 'HR'.
    WRITE: / 'Department: Human Resources Management'.
  WHEN 'FIN'.
    WRITE: / 'Department: Finance & Controlling (FICO)'.
  WHEN 'SAP'.
    WRITE: / 'Department: Enterprise SAP Development Core'.
  WHEN OTHERS.
    WRITE: / 'Department: General Corporate Services'.
ENDCASE.
🖥️ CONSOLE / LIST OUTPUT 
Department: Enterprise SAP Development Core

2.3Master Comparison Operators & Pattern Matching

ABAP supports both standard algebraic operators and 2-letter mnemonic operators. Furthermore, it features powerful character comparison operators (CP, CO, CA, etc.).

Symbol Mnemonic Detailed Meaning & Wildcards Student Example
= EQ Equal to IF lv_status = 'OPEN'.
<> NE Not equal to IF lv_role NE 'ADMIN'.
< LT Less than IF lv_age < 18.
> GT Greater than IF lv_salary GT 50000.
<= LE Less than or equal to IF lv_count <= 100.
>= GE Greater than or equal to IF lv_score >= 75.
BETWEEN — Value inside range: val BETWEEN min AND max IF lv_age BETWEEN 20 AND 30.
IS INITIAL — Checks if variable holds its default blank/zero value IF lv_date IS INITIAL.
CP Pattern Contains Pattern (* = any sequence, + = single char) IF lv_text CP '*SAP*'.
NP No Pattern Does NOT match pattern IF lv_email NP '*@*.*'.
CO Only Contains Only characters from test set IF lv_phone CO '0123456789 -'.
CA Any Contains Any character from test set IF lv_pass CA '!@#$%^&*'.
💻 WORKING PRACTICAL CODE • LINE-BY-LINE COMMENTED ABAP 7.40+ EXECUTABLE 
DATA lv_company TYPE string VALUE 'Infosys Limited'.

" 1. Pattern Matching with CP (Wildcard check)
"    * matches zero or more characters; + matches exactly one character
IF lv_company CP '*Infosys*'.
  WRITE: / 'Match Found: Name contains Infosys'.
ENDIF.

" 2. Character Verification with CO (Contains Only)
"    Useful for input sanitization (ensuring no illegal symbols)
IF lv_company CO 'ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz '.
  WRITE: / 'Sanitized: Contains alphabetic letters and spaces only'.
ELSE.
  WRITE: / 'Alert: Contains numeric or special characters!'.
ENDIF.
🖥️ CONSOLE / LIST OUTPUT 
Match Found: Name contains Infosys
Sanitized: Contains alphabetic letters and spaces only
⚠️ EXAM & DEBUG WATCHOUT: The Missing Wildcards Trap in CP
If you write IF lv_text CP 'Infosys' without asterisks, ABAP checks for an exact match of the word 'Infosys'! If lv_text is 'Infosys Limited', it will evaluate to FALSE! To do a substring search anywhere in the text, you MUST wrap it in wildcards: CP '*Infosys*'.

Structures, Work Areas & Internal Tables

To master ABAP, you must build an instinctive mental picture of data containers:

Container Concept Mental Model Analogy ABAP Keyword Blueprint Rows in Memory
1. Structure (Type) The Architectural Blueprint TYPES: BEGIN OF ty_... END OF ty_... 0 rows (Does not hold data; only defines the shape).
2. Work Area (WA) A Single Printed Form / Clipboard DATA ls_emp TYPE ty_employee. Exactly 1 row (Holds current record being processed).
3. Internal Table (ITAB) The Filing Cabinet / Spreadsheet Grid DATA lt_emp TYPE STANDARD TABLE OF ty_... 0 to Millions of rows (Dynamically grows in RAM).
📊 Visual Concept Diagram: The 3 Core ABAP Data Containers & Row Movement
💡 Student Visual Takeaway: TYPES (Structure) defines the column layout (0 bytes). Work Area (WA) holds exactly 1 active record. Internal Table (ITAB) holds multiple rows. APPEND clones from WA into ITAB; READ TABLE fetches from ITAB into WA.

3.1Defining a Structure Type

📐 SYNTAX BLUEPRINT • WHERE & WHY TO USE WHAT TEMPLATE STRUCTURE 
TYPES: BEGIN OF <ty_structure_name>,
         <field_1> TYPE <data_type_1>,
         <field_2> TYPE <data_type_2>,
         <field_3> TYPE <data_type_3>,
       END OF <ty_structure_name>.
Where & Why to Use What:
  • TYPES: BEGIN OF ... END OF: [Where to use]: Defines a reusable composite row type without consuming RAM.
  • Naming Convention: Always prefix custom row types with ty_ (e.g. ty_employee).
💻 WORKING PRACTICAL CODE • LINE-BY-LINE COMMENTED ABAP 7.40+ EXECUTABLE 
" Define the composite blueprint for an employee record
TYPES: BEGIN OF ty_employee,
         emp_id   TYPE i,
         emp_name TYPE c LENGTH 20,
         dept     TYPE c LENGTH 10,
       END OF ty_employee.

3.2Instantiating and Populating a Work Area

Components of a structure variable are accessed using the hyphen (-) selector.

📐 SYNTAX BLUEPRINT • WHERE & WHY TO USE WHAT TEMPLATE STRUCTURE 
DATA <work_area_name> TYPE <ty_structure_name>.

<work_area_name>-<field_name> = <value_to_assign>.
Where & Why to Use What:
  • DATA ls_emp TYPE ty_employee.: [Where to use]: Allocates single-record memory based on the blueprint.
  • ls_emp-emp_id: [Where to use]: Accesses the individual column field inside the structure.
💻 WORKING PRACTICAL CODE • LINE-BY-LINE COMMENTED ABAP 7.40+ EXECUTABLE 
DATA ls_employee TYPE ty_employee.

" Assign values to each column in the work area
ls_employee-emp_id   = 101.
ls_employee-emp_name = 'Sudhanwa'.
ls_employee-dept     = 'ETA'.

" Output individual fields
WRITE: / 'ID   :', ls_employee-emp_id,
       / 'Name :', ls_employee-emp_name,
       / 'Dept :', ls_employee-dept.
🖥️ CONSOLE / LIST OUTPUT 
ID   :        101
Name : Sudhanwa
Dept : ETA

3.3The VALUE Constructor (Modern ABAP 7.40+)

Instead of tedious line-by-line field assignments, the VALUE #( ... ) constructor operator fills an entire work area in a single expressive statement.

📐 SYNTAX BLUEPRINT • WHERE & WHY TO USE WHAT TEMPLATE STRUCTURE 
<work_area> = VALUE #(<field_1> = <val_1> <field_2> = <val_2> ...).
Where & Why to Use What:
  • # (Pound sign): [Where to use]: Tells the compiler to infer the target type automatically from the left-hand variable.
  • No commas are needed between field assignments inside the parentheses.
💻 WORKING PRACTICAL CODE • LINE-BY-LINE COMMENTED ABAP 7.40+ EXECUTABLE 
" Modern, elegant one-liner instantiation of a work area
ls_employee = VALUE #(
  emp_id   = 102
  emp_name = 'Fahed'
  dept     = 'ETA'
).

WRITE: / 'Constructed Employee:', ls_employee-emp_name, '(', ls_employee-dept, ')'.
🖥️ CONSOLE / LIST OUTPUT 
Constructed Employee: Fahed ( ETA )

3.4Internal Tables (ITAB) & Table Kinds

An Internal Table holds a collection of identically structured rows in RAM session memory.

Table Kind Key Definition Access Performance Where to Use in Practice
STANDARD Linear index; key can be non-unique. Index: $O(1)$ fast.
Linear Key Search: $O(n)$ slow without sort!		 Default general-purpose table. Best for sequential appending and loop processing.
SORTED Always kept strictly sorted by its key. Key Search: $O(\log n)$ logarithmic binary search built-in! Large lookup tables frequently queried by key. Insertion has overhead to preserve sort order.
HASHED Unique key backed by a memory hash table. Key Search: $O(1)$ constant time lookup regardless of size! Master-data caching (e.g. 100,000 customers). Only key access is permitted; no index access allowed.
📐 SYNTAX BLUEPRINT • WHERE & WHY TO USE WHAT TEMPLATE STRUCTURE 
DATA <itab_name> TYPE STANDARD TABLE OF <row_type>
                 WITH EMPTY KEY.

" Multi-row initialization with VALUE #( ... )
<itab_name> = VALUE #(
  ( <field_1> = <val_1> <field_2> = <val_2> )
  ( <field_1> = <val_3> <field_2> = <val_4> )
).
Where & Why to Use What:
  • WITH EMPTY KEY: [Where to use]: Standard modern syntax for tables that don't need a formal primary key constraint.
  • Inner Parentheses ( ... ): [Where to use]: Each set of nested parentheses in VALUE # represents one complete row.
💻 WORKING PRACTICAL CODE • LINE-BY-LINE COMMENTED ABAP 7.40+ EXECUTABLE 
" Declare an internal table to store a roster of employees
DATA lt_employee TYPE STANDARD TABLE OF ty_employee
                 WITH EMPTY KEY.

" Populate the internal table with 3 rows simultaneously
lt_employee = VALUE #(
  ( emp_id = 102 emp_name = 'Fahed' dept = 'ETA' )
  ( emp_id = 103 emp_name = 'Tanvi' dept = 'HR'  )
  ( emp_id = 104 emp_name = 'Hari'  dept = 'SAP' )
).

WRITE: / 'Internal Table successfully populated with', lines( lt_employee ), 'records.'.
🖥️ CONSOLE / LIST OUTPUT 
Internal Table successfully populated with 3 records.

• ty_* : Type definition

Appending, Inserting, Reading, Searching & Duplicates

Managing rows inside internal tables is the bread-and-butter of every ABAP developer. Here is your definitive operation guide:

4.1APPEND: Adding Rows to the End

APPEND takes the current contents of a work area, creates a fresh copy, and attaches it as the new final row of the internal table.

📐 SYNTAX BLUEPRINT • WHERE & WHY TO USE WHAT TEMPLATE STRUCTURE 
APPEND <work_area> TO <internal_table>.
Where & Why to Use What:
  • <work_area>: [Where to use]: The source single-row variable holding the data.
  • <internal_table>: [Where to use]: Target table. Note: Later changes to the work area DO NOT affect the appended row because ABAP creates a copy in memory.
💻 WORKING PRACTICAL CODE • LINE-BY-LINE COMMENTED ABAP 7.40+ EXECUTABLE 
" 1. Prepare work area with new hire details
DATA ls_emp TYPE ty_employee.
ls_emp = VALUE #( emp_id = 105 emp_name = 'Tanvi' dept = 'HR' ).

" 2. Append work area into the internal table
APPEND ls_emp TO lt_employee.

" 3. Alternative: Direct APPEND VALUE (No intermediate work area needed!)
APPEND VALUE ty_employee(
  emp_id   = 106
  emp_name = 'Asha'
  dept     = 'IT'
) TO lt_employee.

4.2INSERT at Specific Index

Unlike APPEND (which only puts rows at the very end), INSERT ... INDEX <n> places a row at a chosen position and shifts subsequent rows down.

📐 SYNTAX BLUEPRINT • WHERE & WHY TO USE WHAT TEMPLATE STRUCTURE 
INSERT <work_area_or_value> INTO <internal_table> INDEX <target_index>.
Where & Why to Use What:
  • INDEX <target_index>: [Where to use]: 1-based target row position. INDEX 1 inserts at the top of the table.
  • If the index exceeds lines(itab) + 1, insertion fails and sets sy-subrc = 4.
💻 WORKING PRACTICAL CODE • LINE-BY-LINE COMMENTED ABAP 7.40+ EXECUTABLE 
" Insert Ravi as the new 2nd row in the table (shifts old row 2 down to row 3)
INSERT VALUE ty_employee(
  emp_id   = 110
  emp_name = 'Ravi'
  dept     = 'SAP'
) INTO lt_employee INDEX 2.

IF sy-subrc = 0.
  WRITE: / 'Successfully inserted at Index 2!'.
ENDIF.

4.3READ TABLE: Key Search vs Binary Search

READ TABLE extracts a single matching record from an internal table into a work area. It sets the critical system return code SY-SUBRC.

📐 SYNTAX BLUEPRINT • WHERE & WHY TO USE WHAT TEMPLATE STRUCTURE 
" 1. Search by Key (Sequential Scan)
READ TABLE <internal_table> INTO <work_area>
     WITH KEY <column_name> = <target_value>.

" 2. Search with High-Performance BINARY SEARCH (Requires prior SORT!)
READ TABLE <internal_table> INTO <work_area>
     WITH KEY <column_name> = <target_value>
     BINARY SEARCH.

" 3. Inspect Return Code immediately after!
IF sy-subrc = 0.
  " Match found; work area is populated!

Local Class Creation & Employee Details

Concept & Mental Model: A Class is an architectural blueprint. An Object is a physical instance built from that blueprint living in session memory. In ABAP, classes always have two distinct mandatory sections: 1. DEFINITION (Declares what attributes and methods exist) and 2. IMPLEMENTATION (Contains the actual executable logic).

15.1Syntax Blueprint: Class Structure & Object Instantiation

📐 SYNTAX BLUEPRINT • WHERE & WHY TO USE WHAT TEMPLATE STRUCTURE 
" --- 1. CLASS DEFINITION BLOCK ---
CLASS <class_name> DEFINITION.
  PUBLIC SECTION.
    DATA <instance_attribute> TYPE <data_type>.
    METHODS <instance_method_name>.
ENDCLASS.

" --- 2. CLASS IMPLEMENTATION BLOCK ---
CLASS <class_name> IMPLEMENTATION.
  METHOD <instance_method_name>.
    <executable_abap_statements>
  ENDMETHOD.
ENDCLASS.

" --- 3. OBJECT CREATION & INVOCATION ---
DATA(<object_ref>) = NEW <class_name>( ).
<object_ref>-><instance_attribute> = <value>.
<object_ref>-><instance_method_name>( ).
Where & Why to Use What:
  • PUBLIC SECTION: [Where to use]: Components accessible from anywhere outside the class.
  • NEW <class_name>( ): [Modern 7.40+]: Instantiates a new object in heap memory (replaces classic CREATE OBJECT lo_obj).
  • -> (Arrow Operator): [Mandatory]: Used to access instance components (attributes and methods) through an object reference variable.

Static Keyword in ABAP (CLASS-DATA & CLASS-METHODS)

Concept & Mental Model: Static components belong to the Class itself, not to individual object instances. There is exactly one single shared copy in memory, shared across all objects. You do NOT need to create an object (NEW) to call static methods!

📊 Visual Concept Diagram: Instance Objects (->) vs Class-Level Static Memory (=>)
💡 Student Visual Takeaway: Each object created with NEW allocates its own independent instance data accessed via ->. Static components (CLASS-DATA) exist as a single shared copy accessed via the class name => without instantiating any object.

16.1Syntax Blueprint: Static Component Selector (=>)

📐 SYNTAX BLUEPRINT • WHERE & WHY TO USE WHAT TEMPLATE STRUCTURE 
CLASS <class_name> DEFINITION.
  PUBLIC SECTION.
    CLASS-DATA <static_attribute> TYPE <data_type>.
    CLASS-METHODS <static_method_name>.
ENDCLASS.

" Invoking directly via class name using double-arrow (=>)
<class_name>=><static_attribute> = <value>.
<class_name>=><static_method_name>( ).
Where & Why to Use What:
  • CLASS-DATA: [Where to use]: Declares a static attribute shared across all instances.
  • CLASS-METHODS: [Where to use]: Declares a static method. Can be invoked directly without instantiating an object.
  • => (Fat Arrow / Double Arrow): [Mandatory]: Used to access static components directly through the class name.

IMPORTING & EXPORTING Parameters

Concept & Mental Model: Methods communicate data using parameters. IMPORTING brings input data INTO the method. EXPORTING sends calculated output data BACK to the caller.

📊 Visual Concept Diagram: The 4 Method Parameter Directions & Data Flow Channels
💡 Student Visual Takeaway: IMPORTING brings data IN. EXPORTING returns data OUT. CHANGING modifies values in-place (two-way). RETURNING VALUE returns exactly one functional result directly into an assignment expression.

17.1Syntax Blueprint: Parameter Definition vs Invocation Perspective

📌 The Flip-Flop Perspective (Important Student Trap!)
Watch the perspective switch between declaration and calling:
  • In the Method Definition: Parameters are named from the Method's perspective (IMPORTING means method receives; EXPORTING means method returns).
  • At the Caller Call-site: The keywords invert! The caller EXPORTING passes values in, and IMPORTING catches the results!
📐 SYNTAX BLUEPRINT • WHERE & WHY TO USE WHAT TEMPLATE STRUCTURE 
" 1. IN METHOD DECLARATION:
METHODS <method_name>
  IMPORTING <im_input_param>  TYPE <data_type>
  EXPORTING <ex_output_param> TYPE <data_type>.

" 2. IN METHOD IMPLEMENTATION:
METHOD <method_name>.
  <ex_output_param> = <im_input_param> + <calculation>.
ENDMETHOD.

" 3. AT CALLER SITE (Notice perspective!):
<object_ref>-><method_name>(
  EXPORTING <im_input_param>  = <caller_source_value>
  IMPORTING <ex_output_param> = <caller_target_variable>
).
Where & Why to Use What:
  • IMPORTING (at definition): Input parameter accepted by the method.
  • EXPORTING (at definition): Output parameter generated by the method.
  • At Call-site: EXPORTING feeds the input; IMPORTING captures the output.

Concept & Mental Model: When you need a parameter to act as both an input AND an output simultaneously, use CHANGING. The method receives the caller's variable, modifies it directly in place, and the caller sees the updated value immediately.

📐 SYNTAX BLUEPRINT • WHERE & WHY TO USE WHAT TEMPLATE STRUCTURE

).
Where & Why to Use What:
  • CHANGING: [Where to use]: When you want to update an existing variable in place rather than declaring separate input and output parameters.

RETURNING VALUE in ABAP (Functional Expressions)

Concept & Mental Model: A method with a RETURNING VALUE(...) is known as a Functional Method. It returns exactly one return value, allowing the method call to be embedded directly into arithmetic expressions, assignments, or IF conditions — exactly like functions in Java, Python, or C#!

19.1Syntax Blueprint: Functional Method Declaration & Direct Assignment

📐 SYNTAX BLUEPRINT • WHERE & WHY TO USE WHAT TEMPLATE STRUCTURE 
" 1. IN METHOD DECLARATION:
METHODS <method_name>
  IMPORTING <im_param> TYPE <data_type>
  RETURNING VALUE(<rv_result_param>) TYPE <return_data_type>.

" 2. IN METHOD IMPLEMENTATION:
METHOD <method_name>.
  <rv_result_param> = <im_param> + <calculation>.
ENDMETHOD.

" 3. AT CALLER SITE (Direct Functional Assignment!):
<target_variable> = <object_ref>-><method_name>( <caller_input> ).
Where & Why to Use What:
  • RETURNING VALUE(<name>): [Where to use]: The keyword VALUE is mandatory around the returning parameter name.
  • Single Return Rule: A method can have only ONE RETURNING parameter.
  • Mutual Exclusion: A method with RETURNING CANNOT have EXPORTING or CHANGING parameters!

Inheritance • Parent & Child Classes

Concept & Mental Model: Inheritance allows a specialized Child Class (Subclass) to inherit all public and protected attributes and methods from an existing Parent Class (Superclass). The child acquires all features of the parent without copying a single line of code!

📊 Visual Concept Diagram: Object-Oriented Inheritance & Method Redefinition (Polymorphism)
💡 Student Visual Takeaway: The child subclass inherits all components from the parent. Using REDEFINITION, the child replaces the parent's method implementation with its own specialized logic, while retaining the ability to call the parent version via super->display().

20.1Syntax Blueprint: Subclassing with INHERITING FROM

📐 SYNTAX BLUEPRINT • WHERE & WHY TO USE WHAT TEMPLATE STRUCTURE 
CLASS <child_class_name> DEFINITION
  INHERITING FROM <parent_class_name>.
  PUBLIC SECTION.
    METHODS <child_specific_method>.
ENDCLASS.
Where & Why to Use What:
  • INHERITING FROM: [Where to use]: Placed in the class definition header to declare parentage.
  • Single Inheritance: In ABAP, a class can inherit from only ONE parent superclass (No multiple class inheritance; use Interfaces for multiple contracts).
  • Visibility Rules:
    • PUBLIC: Accessible everywhere.
    • PROTECTED: Accessible inside parent and all its child subclasses.
    • PRIVATE: Accessible ONLY inside the declaring parent class (Subclasses CANNOT touch private components!).

Method Redefinition • Polymorphism in Action

Concept & Mental Model: What if the child inherits a method from the parent, but needs to override its behavior? Using REDEFINITION, the child provides its own custom implementation while preserving the exact same method signature!

21.1Syntax Blueprint: REDEFINITION Clause

📐 SYNTAX BLUEPRINT • WHERE & WHY TO USE WHAT TEMPLATE STRUCTURE 
CLASS <child_class_name> DEFINITION
  INHERITING FROM <parent_class_name>.
  PUBLIC SECTION.
    METHODS <inherited_method_name> REDEFINITION.
ENDCLASS.

CLASS <child_class_name> IMPLEMENTATION.
  METHOD <inherited_method_name>.
    " Optional: Call parent original logic first using super->
    super-><inherited_method_name>( ).
    <new_custom_subclass_logic>
  ENDMETHOD.
ENDCLASS.
Where & Why to Use What:
  • METHODS <name> REDEFINITION: [Where to use]: Declares that this class is overriding the inherited method.
  • Do NOT repeat parameter declarations (IMPORTING/EXPORTING) in the redefinition — signature is inherited automatically!
  • super-><method>: [Where to use]: Pseudo-reference to invoke the original superclass logic before or after custom logic.

  • USING <tables>: [Mandatory]: Must list every database table or view referenced inside the SQLScript query so SAP creates database dependency locks.

Core Data Services (CDS) Views & Eclipse ADT

In classic ABAP, developers extracted raw tables to the application server and processed them line-by-line using loops. With SAP S/4HANA and in-memory computing, SAP introduced Core Data Services (CDS) Views. CDS views push calculations, joins, aggregations, and business logic directly down into the database engine (Code Pushdown), delivering up to 100x faster execution while serving as the universal semantic foundation for SAP Fiori, OData services, and the ABAP RESTful Application Programming Model (RAP).

📌 STUDENT NOTE: The Mental Shift: Database as a Computation Engine, Not Just a Disk
Think of classic database tables like ingredients in a warehouse and the application server as a single chef. In classic ABAP, the chef carried 100,000 raw tomatoes upstairs to make soup. With CDS, the warehouse has a robotic kitchen that delivers ready-made soup straight to your table! That is the essence of Code Pushdown.

💡 Student Visual Takeaway: In traditional ABAP, massive data was pulled to the application server and processed line-by-line. With CDS Views, calculation logic is pushed down directly into the SAP HANA in-memory database engine, returning only the ready-to-consume aggregated result set.

24.1What is a CDS View & Why is it Superior to Classic SE11 Views?

A CDS View (Core Data Services) is an enhancement of SQL that defines semantically rich data models directly in the database. While a classic SE11 View is merely a basic projection or inner join, a CDS view supports expressions, associations, aggregations, case statements, and annotations.

Feature / Capability Classic SE11 Database View Modern ABAP CDS View
Where It Executes Basic projection on DB; logic in ABAP memory. 100% inside SAP HANA In-Memory Database.
Where You Create It SAP GUI transaction SE11. Eclipse IDE + ABAP Development Tools (ADT).
Calculated Fields & CASE ❌ Not supported (only raw table fields). ✅ Supported (case when ... then ..., string & math formulas).
Joins & Associations Rigid Inner Joins executed immediately. On-Demand Associations (fetched only when accessed).
Fiori & UI Generation ❌ None (manual Gateway SEGW required). ✅ Direct Fiori UI metadata via @UI annotations.
RAP Hierarchy ❌ Not supported. ✅ Native composition and parent links for RAP.

Simple & Practical Error Handling in ABAP

In business software, errors are guaranteed to happen: a user enters a blank customer ID, an order item has a quantity of 0 causing a division by zero, or a requested invoice record does not exist in the database. Without error handling, the ABAP runtime terminates immediately with an ugly Runtime Short Dump (Transaction ST22), losing user unsaved data and halting production. Mastering Error Handling means installing safety nets so your programs catch issues gracefully, log warnings, and guide the user cleanly.

📊 Visual Concept Diagram: ABAP Exception Handling: Unhandled Crash vs TRY...CATCH Safety Net
💡 Student Visual Takeaway: Without error handling, runtime arithmetic faults or bad table lookups cause an immediate ST22 Short Dump and crash the user session. Wrapping critical code in a TRY ... CATCH block acts as an enterprise safety net, gracefully logging errors without terminating the program.

25.1The Two Paradigms: Classic Return Codes vs Class-Based Exceptions

In ABAP, you have two primary mechanisms to manage errors:

Mechanism How It Works When to Use It
sy-subrc Check
(Classic Return Code)		 Every database query, table search, or function call automatically sets system field sy-subrc.
• sy-subrc = 0: Success!
• sy-subrc <> 0: Failed / Not Found.		 Standard data retrieval: SELECT SINGLE, READ TABLE, AUTHORITY-CHECK, and legacy function modules.
TRY ... CATCH
(Class-Based Exceptions)		 When an error occurs, an exception object inheriting from cx_root is instantiated and thrown. The CATCH block traps it before the program crashes. Mathematical calculations (division by zero), object method calls, REST/OData APIs, AMDP calls, and modern OO-ABAP development.

25.2Method 1: Checking sy-subrc (The Golden Habit)

The number one rule every ABAP student must memorize: Never assume a database query or table lookup was successful! Always check sy-subrc immediately on the very next line.

📐 CLASSIC RETURN CODE BLUEPRINT (sy-subrc) TEMPLATE STRUCTURE 
<ABAP_STATEMENT_THAT_SETS_SUBRC>
IF sy-subrc = 0.
  " SUCCESS: Target record was found / action succeeded!
  <proceed_with_business_logic>
ELSE.
  " FAILURE: Record not found (sy-subrc is usually 4 or 8)
  <handle_missing_record_or_display_error>
ENDIF.
Where & Why to Use What:
  • <ABAP_STATEMENT>: Any statement like SELECT SINGLE, READ TABLE, or AUTHORITY-CHECK.
  • sy-subrc = 0: 0 always means absolute success. Memory contains valid data.
  • sy-subrc <> 0: Non-zero (most commonly 4) means no record was matched.
  • Rule: Do NOT put other statements between the operation and the IF sy-subrc check, or sy-subrc might get overwritten!

25.3Method 2: Modern Exception Handling (TRY ... CATCH ... ENDTRY)

Certain runtime errors cannot be prevented with simple sy-subrc checks. For example, dividing by zero in ABAP triggers an instant system dump CX_SY_ZERODIVIDE. To prevent the dump, we wrap risky calculations or method calls in a TRY ... CATCH block.

📐 MODERN EXCEPTION BLUEPRINT (TRY...CATCH) TEMPLATE STRUCTURE 
TRY.
    " 1. Risky code that might throw an exception
    <risky_arithmetic_or_object_call>

  CATCH <exception_class_name> INTO DATA(<lx_exception_instance>).
    " 2. Trapped safely! Extract error text and recover
    DATA(lv_error_message) = <lx_exception_instance>->get_text( ).
    <display_or_log_error_message>

  CLEANUP.
    " 3. Optional: Executes if an unhandled exception exits this block
    <close_open_files_or_reset_resources>
ENDTRY.
Where & Why to Use What:
  • TRY.: Begins the guarded safety zone.
  • CATCH <class> INTO DATA(<lx>): Traps a specific exception (e.g. cx_sy_zerodivide) or universal root cx_root. Inline declares the exception object lx.
  • lx->get_text( ): Method inherited from cx_root that returns the human-readable explanation of why the crash happened.
  • CLEANUP.: Optional safety block to clean up memory or connections if an exception propels outward.
  • ENDTRY.: Closes the exception handler.

Catch specific exceptions first (CATCH cx_sy_zerodivide, CATCH cx_sy_conversion_no_number), and only place the universal catch-all (CATCH cx_root) at the very bottom. If you catch cx_root first, it catches everything and conceals specific bug root causes!
